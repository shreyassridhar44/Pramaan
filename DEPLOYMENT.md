# Deployment

## 1. Local

Prerequisites: Docker Desktop, Node.js 22 or later, Python 3.12, `uv`.

1. `cp .env.example .env` and adjust if needed.
2. `docker compose -f infra/compose.dev.yml up -d` starts Postgres, Valkey and Mailpit. Documents are stored under `.data/storage` locally.
3. API: `cd services/api && uv sync && uv run alembic upgrade head && uv run python -m scripts.seed && uv run uvicorn app.main:app --reload`
4. Worker: `cd services/api && uv run arq app.workers.settings.WorkerSettings`
5. Web: `cd apps/web && npm install && npm run dev`, then open http://localhost:5173
6. Mailpit inbox: http://localhost:8025

## 2. AWS (ap-south-1)

Budget: the account is on the AWS Free plan ($95 of credit left on 26 October 2026, plan ends 20 January 2027), which allows only free-tier instance types. The deployment costs about $15 a month, so it can stay on until January. Scripts and their usage: `infra/aws/README.md`. Design choices: DECISION D33.

### 2.1 Resources

| Resource | Configuration | Estimated monthly cost |
|---|---|---|
| EC2 | t4g.small (2 vCPU, 2 GB, Graviton, free-tier eligible), Amazon Linux 2023 arm64, 30 GB gp3 encrypted, 3 GB swap, IMDSv2 only | $8.2 + $2.7 |
| Elastic IP | Stable address, so the URL survives a stop and start | $3.6 |
| HTTPS | Caddy on the instance with a Let's Encrypt certificate for `<ip-with-dashes>.sslip.io`; CloudFront (`EDGE=cloudfront`) once AWS verifies the account for it | free |
| S3 | `pramaan-<account>-ap-south-1`: release bundles (30 days) and backups (14 days); private, encrypted | under $1 |
| SSM Parameter Store | `/pramaan/*` SecureString secrets, generated by the script | free (standard tier) |

On the instance, `infra/compose.yml` runs Postgres, Valkey, the API (one uvicorn worker, trained models baked into the image and loaded at start-up), the arq worker (daily monitoring and outbox), Mailpit (captured inbox at `/mail/`, password-protected), nginx (web app and API proxy) and Caddy (HTTPS entry point). Bedrock stays off until model access is granted (DECISION D29).

### 2.2 Steps

1. `bash infra/aws/provision.sh`: bucket, instance role, secrets, security group (ports 80 and 443; no SSH), instance, Elastic IP, and the public host name. Prints the public URL.
2. `bash infra/aws/deploy.sh`: uploads the committed `HEAD`, then on the instance writes `infra/.env` from SSM, builds the images, migrates, seeds on the first deploy, starts the stack, and installs the nightly backup timer.
3. Verify: `https://<ip-with-dashes>.sslip.io/api/v1/readyz` reports every check `ok` (the deploy prints it); sign in with a persona; upload the altered specimen.
4. `bash infra/aws/enable-autodeploy.sh` once. From then on every push to `main`, by anyone on the team, is deployed within about 2 minutes plus build time, and a release that fails its health check is rolled back (DECISION D35). `bash infra/aws/ops.sh autodeploy-log` shows what was deployed.
5. Reset the demo data with `SEED=1 bash infra/aws/deploy.sh` from an up-to-date `main`, or `POST /api/v1/demo/reset` as the admin persona.

### 2.3 Operating the budget

- `bash infra/aws/ops.sh stop` saves about $8 a month when the site is not needed (disk and Elastic IP still cost about $6 a month); `ops.sh start` brings it back on the same URL.
- A t4g.medium (4 GB) is not allowed on the Free plan; the x86 "flex" types that are allowed cost $61 to $73 a month. On 2 GB the API runs one worker and a receipt analysis takes several seconds; the memory limits in `infra/compose.yml` are sized from measured peaks.
- The account budget alarm is set at $100 per month.

## 3. Health checks

- `/api/v1/healthz`: process alive (used by the API container's health check).
- `/api/v1/readyz`: database, queue (Valkey), document storage and model files. A missing model reads "missing ... (classical fallback)" and the status is `degraded`.
- Every container restarts on failure (`restart: unless-stopped`); `bash infra/aws/ops.sh status` and `ops.sh logs <service>` show state and logs without SSH.

## 4. Rollback

Each deploy is named by its commit, and the instance keeps the three newest releases. Roll back with `git checkout <previous-commit> && bash infra/aws/deploy.sh`, then return to `main`. Data is untouched by a rollback; restore a backup only if a migration has to be undone (`infra/aws/README.md`).
