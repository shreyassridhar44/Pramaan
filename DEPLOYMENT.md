# Deployment

## 1. Local

Prerequisites: Docker Desktop, Node.js 22 or later, Python 3.12, `uv`.

1. `cp .env.example .env` and adjust if needed.
2. `docker compose -f infra/compose.dev.yml up -d` starts Postgres, Valkey and Mailpit. Documents are stored under `.data/storage` locally.
3. API: `cd services/api && uv sync && uv run alembic upgrade head && uv run python -m scripts.seed && uv run uvicorn app.main:app --reload`
4. Worker: `cd services/api && uv run arq app.workers.settings.WorkerSettings`
5. Web: `cd apps/web && npm install && npm run dev`, then open http://localhost:5173
6. Mailpit inbox: http://localhost:8025

## 2. AWS (ap-south-1)

Budget target: about $23 per month while running, so that the $100 credit lasts to January when the instance is stopped between demos. Scripts and their usage: `infra/aws/README.md`. Design choices: DECISION D33.

### 2.1 Resources

| Resource | Configuration | Estimated monthly cost |
|---|---|---|
| EC2 | t4g.medium (2 vCPU, 4 GB, Graviton), Amazon Linux 2023 arm64, 30 GB gp3 encrypted, 2 GB swap, IMDSv2 only | $16.4 + $2.7 |
| Elastic IP | Stable origin address across stop and start | $3.6 |
| CloudFront | One distribution, one origin (the instance, HTTP with a secret header); HTTPS with the default certificate; only `/assets/*` cached | free tier at demo volume |
| S3 | `pramaan-<account>-ap-south-1`: release bundles (30 days) and backups (14 days); private, encrypted | under $1 |
| SSM Parameter Store | `/pramaan/*` SecureString secrets, generated by the script | free (standard tier) |

On the instance, `infra/compose.yml` runs Postgres, Valkey, the API (two uvicorn workers, trained models baked into the image), the arq worker (daily monitoring and outbox), Mailpit (captured inbox at `/mail/`, password-protected) and nginx (web app and API proxy). Bedrock stays off until model access is granted (DECISION D29).

### 2.2 Steps

1. `bash infra/aws/provision.sh`: bucket, instance role, secrets, security group (port 80 from CloudFront's origin-facing prefix list only, no SSH), instance, Elastic IP, CloudFront distribution. Prints the public URL.
2. `bash infra/aws/deploy.sh`: uploads the committed `HEAD`, then on the instance writes `infra/.env` from SSM, builds the images, migrates, seeds on the first deploy, starts the stack, and installs the nightly backup timer.
3. Verify: `https://<distribution>.cloudfront.net/api/v1/readyz` reports every check `ok`; sign in with a persona; upload the altered specimen.
4. Later deploys: commit, then `bash infra/aws/deploy.sh` (`SEED=1` resets the demo data).

### 2.3 Operating the budget

- `bash infra/aws/ops.sh stop` when not needed (disk and Elastic IP still cost about $6 a month); `ops.sh start` before evaluations and demos. The URL does not change.
- The account budget alarm is set at $100 per month.

## 3. Health checks

- `/api/v1/healthz`: process alive (used by the API container's health check).
- `/api/v1/readyz`: database, queue (Valkey), document storage and model files. A missing model reads "missing ... (classical fallback)" and the status is `degraded`.
- Every container restarts on failure (`restart: unless-stopped`); `bash infra/aws/ops.sh status` and `ops.sh logs <service>` show state and logs without SSH.

## 4. Rollback

Each deploy is named by its commit, and the instance keeps the three newest releases. Roll back with `git checkout <previous-commit> && bash infra/aws/deploy.sh`, then return to `main`. Data is untouched by a rollback; restore a backup only if a migration has to be undone (`infra/aws/README.md`).
